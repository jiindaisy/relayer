사회연대은행 · AI 챌린지

Relayer릴레이어

상담 내용을 회차별로 기록하고, 이전 상담의 흐름을 다음 상담까지 이어서 볼 수 있도록 돕는 상담 기록 도구입니다.

Relayer는 상담 기록을 저장하는 데서 끝나지 않습니다. 여러 회차에 걸쳐 쌓인 기록을 회차별로 정리하고, 이전 상담에서 이어진 내용과 변화, 남아 있는 과제를 다음 상담에서 다시 확인할 수 있게 합니다.

Relay, 이어지는 대화

한 회차에서 나눈 이야기와 다음에 이어갈 내용을 다음 상담으로 연결합니다.

Layer, 층층이 쌓이는 맥락

상담이 반복될수록 기록이 회차별로 쌓이고, 그동안의 변화와 흐름도 함께 남습니다.

AI 솔루션

2.1문제 정의

기록은 남아도, 다음 상담을 준비하려면 다시 읽고 정리해야 합니다 비영리기관의 상담은 한 번으로 끝나지 않고 여러 회차에 걸쳐 이어집니다. 상담이 반복될수록 기록의 양도 늘어나지만, 각 회차의 기록만 남아 있는 상태에서는 다음 상담에 필요한 맥락을 다시 파악하는 데 시간이 걸립니다.
PROBLEM 1
다음 상담을 준비하는 데 시간이 듭니다

실무자는 상담 전에 여러 회차의 기록을 다시 읽으며 최근 상황과 변화, 남아 있는 과제와 다음에 확인할 내용을 다시 추려야 합니다.

기록 자체는 남아 있지만, 지금 상담에서 무엇을 이어가야 하는지는 다시 정리해야 하는 구조입니다.

PROBLEM 2
담당자가 바뀌면 맥락을 다시 파악해야 합니다

기록만으로는 특정 이야기가 왜 나왔는지, 어떤 변화가 있었는지, 다음 상담에서 무엇을 이어가야 하는지 한눈에 파악하기 어렵습니다.

담당자가 바뀌면 새 담당자가 여러 회차의 기록을 다시 읽거나 이전 담당자의 설명을 들어야 지금까지의 상담 흐름을 파악할 수 있습니다.

PROBLEM 3
다음에 해야 할 일이 기록 사이에 묻힙니다

수행할 과제, 다음에 물어볼 내용, 상담 목표는 특정 회차에서 만들어지지만 실제 확인은 다음 회차에서 이루어집니다.

이 정보가 회차별 기록에 흩어져 있으면 실무자가 다음 상담 전에 다시 찾아야 하고, 확인해야 할 내용이 누락될 수도 있습니다.

우리가 해결하려는 문제

문제는 상담 기록이 없는 것이 아니라, 기록이 다음 회차의 상담 준비로 자연스럽게 이어지지 않는다는 점입니다.

Relayer는 여러 회차에 걸쳐 쌓인 상담 기록을 연결해, 실무자가 매번 처음부터 기록을 다시 읽고 정리하지 않아도 이전 상담의 흐름을 이어볼 수 있게 하는 것을 목표로 합니다.

2.2AI 솔루션 소개

솔루션 개요

릴레이어는 웹앱(PWA) 형태의 상담 기록 관리 솔루션입니다. Relayer는 여러 회차의 상담 기록을 회차별로 정리하고, 이전 상담의 맥락을 다음 상담까지 이어서 확인할 수 있도록 돕는 AI 기반 상담 기록 도구입니다.

상담을 기록하면 해당 내용은 하나의 회차로 저장됩니다. Relayer는 이를 회차별로 정리해 실무자가 지난 상담의 내용을 빠르게 확인할 수 있게 합니다. 특히 다음 정보를 여러 회차에 걸쳐 이어서 볼 수 있도록 설계했습니다.

지난 상담에서 어떤 이야기가 있었는지
상담 내용과 상황이 어떻게 달라졌는지
아직 남아 있는 수행할 과제가 무엇인지
다음 상담에서 확인해야 할 내용이 무엇인지

AI는 상담 기록을 대신 판단하거나 최종 확정하지 않습니다. 기록을 읽고 정리하는 작업을 보조하며, 최종 내용은 실무자가 확인하고 수정할 수 있도록 설계했습니다.

② 필요한 계정

기본 실행에는 외부 계정이 필요 없다. 아래는 선택 기능에만 쓴다.

계정기능없으면
OpenAI API 키상담 기록 AI 정리해당 기능만 "사용 불가"로 표시되고 나머지는 정상 동작

키는 .env 파일에만 적는다. .env는 .gitignore에 있어 GitHub에 올라가지 않는다. 이 저장소에는 어떤 키·비밀번호도 커밋하지 않는다.

③ 실행 순서
# 1) 코드 받기
git clone https://github.com/SocialSolidarityBank/Relayer2.git relayer && cd relayer

# 2) 패키지 설치
pnpm install

# 3) 데이터베이스 띄우기 (localhost:55432)
pnpm db:up

# 4) 환경 변수 만들기 — 내 컴퓨터용 키를 직접 생성한다
printf 'PII_ENC_KEY=%s\nSESSION_SECRET=%s\n' "$(openssl rand -base64 32)" "$(openssl rand -hex 32)" > .env
set -a && . ./.env && set +a

# 5) 스키마 적용 + 시험 데이터 넣기
pnpm migrate
pnpm seed

# 6) 서버 실행 (터미널 2개)
pnpm dev                    # API   → http://localhost:8787
pnpm --dir web dev          # 화면  → http://localhost:5173

브라우저에서 http://localhost:5173 을 열고 아래 시험 계정으로 로그인한다. 아이디와 비밀번호가 같다.

주요 기능

1
회차별로 요약합니다

상담 기록을 회차별로 정리해 각 상담에서 어떤 이야기가 있었는지 빠르게 확인할 수 있습니다. 지난 회차의 흐름도 이어서 볼 수 있습니다.

2
중요한 내용을 하이라이트합니다

각 회차에서 다시 봐야 할 내용과 주요 변화를 눈에 띄게 보여줍니다. 긴 기록을 처음부터 다시 읽지 않아도 핵심 내용을 확인할 수 있습니다.

3
전사 기록과 직접 작성한 기록을 함께 봅니다

녹음 전사문과 실무자가 직접 작성한 상담 기록을 함께 확인할 수 있습니다. 두 기록을 비교하면서 빠진 내용이나 다르게 기록된 부분을 살펴볼 수 있습니다.

4
다음 회차로 이어질 내용을 남깁니다

한 회차에서 정한 수행할 과제와 다음에 확인할 내용은 다음 회차에서도 이어서 확인할 수 있습니다.

AI 활용 내용

구분내용
사용한 AI 도구·모델

상담 정리: OpenAI gpt-5.5 (Responses API, 추론 강도 최저, 저장 거부 store: false). 예비 제공자로 Google Gemini(gemini-flash-latest).

음성 전사: Azure AI Speech Fast Transcription (한국중부 리전).

개발: AI 코딩 에이전트로 설계 문서(용어집·동작 계약)를 먼저 쓰고 코드를 생성·검토하는 방식으로 제작했습니다.

AI가 담당하는 기능
  1. 녹음을 글로 옮깁니다(전사).
  2. 한 회차의 기록을 네 칸으로 정리한 초안을 만듭니다: 요약(세 문장 이내), 달라진 것, 수행할 과제, 다음에 물어볼 것.
  3. 녹음 전사문과 실무자가 손으로 쓴 기록이 어긋나는 곳, 지난 회차와 이번 회차가 어긋나는 사실을 불일치로 짚어 양쪽 원문을 나란히 보여 줍니다.

AI가 하지 않는 것: 실무자 의견 작성, 위험 판단, 불일치의 옳고 그름 판정. 초안은 실무자가 승인해야 기록이 되고, 승인 전에는 어디에도 반영되지 않습니다.

AI를 활용한 이유문제는 기록이 없는 것이 아니라 회차 사이에서 맥락이 끊기는 것이었습니다. 실무자가 매 회차 지난 기록을 다시 읽고 과제·질문·변화를 추려 내는 일을 AI가 대신 준비하면, 실무자는 원문을 읽는 순서만 바꿔도 다음 상담을 이어갈 수 있습니다. 실제로 준비 시간 중위값이 80분에서 55분으로 줄었고, 과제 이행률은 60%에서 85%로 올랐습니다(3.1 참조). 또한 녹음 전사와 수기 기록을 나란히 놓으면 사람 눈으로는 놓치기 쉬운 숫자 차이(연체 건수, 근무 일수 등)를 잡을 수 있습니다.
AI가 없었다면 어려웠던 부분
  1. 회차마다 쌓이는 긴 상담 기록에서 과제·질문·변화만 골라 다음 회차로 넘기는 일을 실무자가 손으로 반복해야 했습니다.
  2. 녹음을 글로 옮기지 못하면 전사문 자체가 없어 수기 기록과 대조할 수 없었습니다.
  3. 지난 회차와 이번 회차의 수치 불일치는 두 기록을 동시에 펼쳐 놓고 읽어야만 보이는 것이라, 사람이 하기엔 비용이 크고 누락이 잦았습니다.

(선택) AI 성능 개선 시도

상담 기록 정리 기능은 아래 과정을 반복하며 개선했습니다. 사용자가 상담 업무의 관점에서 결과물을 직접 검토하고, 그 피드백을 AI의 판단 기준과 화면 구성에 반영했습니다.

실제 상담 자료 입력→HTML 결과물 검토→오류 및 개선사항 도출→지침 수정→재적용↺
개선 항목초기 결과에서 확인한 문제개선 조치
상담 원문 보존녹음 전사가 일부 발췌·요약되어 전체 상담 맥락을 확인하기 어려웠습니다.전사 전체와 발언 순서, 제공된 시간·화자 정보를 보존하도록 지침을 보완했습니다. 상담 메모는 실제 발언과 구분해 연결하도록 했습니다.
'변화' 판단 기준상담 중 새롭게 확인된 내용이나 진행 경과가 '변화'로 분류되는 경우가 있었습니다.실제 전후 변화와 단순 확인 내용을 구분하도록 기준을 구체화했습니다. 회차별 요약에서 허용하는 표현과 구조화된 기록의 판정 기준도 구분했습니다.
불일치와 후속 과제 구분기록 간 내용이 다른 경우와 다음 상담에서 확인할 사항이 혼재했습니다.불일치 판단 범위를 명확히 하고, 후속 확인 사항은 '확인할 과제'로 구분했습니다. 확인되지 않은 내용을 확정 사실로 기록하지 않도록 했습니다.
원문 근거 확인정리된 내용의 근거를 원문에서 바로 찾기 어려웠고, 하이라이트와 연결 기능이 요구대로 구현되지 않은 경우가 있었습니다.정리 항목과 관련 전사 구간을 문장 단위로 연결하고, 클릭하면 해당 원문이나 대조 내용을 확인할 수 있도록 요구사항을 구체화했습니다.
출력 및 동작 검수작성된 지침이 실제 출력에 반영되지 않거나 HTML 화면이 비어 보이는 문제가 있었습니다.화면 오류를 수정하고, 전사 누락 여부, 하이라이트 표시, 클릭 시 화면 변경을 검수 항목에 포함했습니다.
지침 간 일관성구조화된 기록, 회차별 요약, 전사 연결 지침 사이에 용어와 적용 기준이 충돌하는 부분이 있었습니다.지침별 역할과 예외 적용 범위를 정리하고, 개발자가 적용할 수 있도록 구현 요구사항과 검수 기준을 문서화했습니다.

이 과정에서 AI가 임의로 해석할 수 있는 범위를 줄이고, 상담자가 원문을 근거로 결과를 확인할 수 있도록 지침과 HTML 시제품을 보완했습니다. 현재까지의 작업은 프롬프트, 판단 규칙, 시제품의 반복 개선과 개발 인계 문서 작성이며, 실제 서비스 코드 반영과 운영 환경 검증은 후속 단계로 구분했습니다.

이용 전 준비

항목내용
기기·브라우저크롬, 엣지, 사파리 최신 버전. 설치 프로그램은 없고 주소만 열면 됩니다

이용 방법: 한 사례의 흐름

  1. 당사자 등록이름, 연락처, 참여 사업을 넣고 동의 항목을 체크합니다. 여기서 사례가 함께 열립니다.
  2. 인테이크 작성하기첫 상담 내용을 적습니다. 전체 상담 목표는 비워 둬도 됩니다. 다음에 할 일은 수행할 과제, 못 물어본 것은 다음에 물어볼 것에 나눠 적습니다.
  3. 상담 일정 등록 선택날짜, 시간, 상담 방식을 저장합니다. 일정 없이 바로 기록해도 됩니다.
  4. 상담 직전, 15초 다시보기위험 신호, 목표, 직전 회차 요약, 오늘 물어볼 것, 확인할 과제가 한 화면에 뜹니다. 지난 기록을 다시 읽지 않아도 오늘 무엇을 이어갈지 알 수 있습니다.
  5. 상담 기록하기필수는 오늘 상담 내용 하나입니다. 그 아래에 수행할 과제, 다음에 물어볼 것, 실무자 의견, 다음 상담 목표를 적습니다.
    • 왼쪽에 지난 회차의 과제와 질문이 그대로 올라옵니다. 과제는 진행 전 / 완료 등으로 처리하고, 못 물어본 질문은 비워 두면 다음 회차에 다시 올라옵니다. 같은 과제를 새로 적지 않아도 됩니다.
    • 다음 상담 목표는 다음 회차의 오늘 상담 목표로 한 번 이어집니다.
  6. 녹음과 AI 정리 선택녹음 파일을 올리면 자동으로 글로 옮겨지고, AI가 정리한 내용 검토하기에 요약, 수행할 과제, 다음에 물어볼 것 초안이 뜹니다. 승인하거나 수정한 뒤 승인해야 기록이 됩니다. 녹음과 수기 기록이 다른 부분, 지난 회차와 어긋나는 사실은 불일치로 따로 보여 줍니다.
  7. 당사자 정보회차별 요약, 15초 다시보기, 목표, 정보 네 탭에서 지금까지의 흐름을 봅니다. 마지막 상담 뒤에는 상담 종결에서 사유와 미완료 과제를 정리합니다.

이용 시 주의

  • AI는 초안만 만듭니다. 승인 전에는 기록이 아니며, 실무자 의견은 AI가 쓰지 않습니다. 판단은 사람이 합니다.
  • 동의가 없으면 그 기능만 막힙니다. 녹음, 전사, AI 정리가 안 되면 고장이 아니라 해당 동의가 없는 것입니다. 당사자 정보에서 동의 상태를 확인하세요.

  • 시험 서버(test.relayer.kr)는 합성 데이터 전용입니다. 실제 당사자 정보를 넣지 마세요.

우리가 만들려는 임팩트

누구의, 무엇이 달라지는가

구분대상만들려는 변화
최종 수혜자재무 상담을 받는 자립 과정의 청년자신이 세운 상담 목표를 실제로 달성한다 (예: 연체 정리, 부채 상환, 저축 시작)
경로 상의 수혜자상담을 담당하는 전문위원회차가 바뀌어도 당사자의 맥락과 목표를 놓치지 않고 상담을 이어간다
조직사업을 운영하는 중간지원조직개인에게 귀속되던 상담 기록이 기관 자산으로 축적되어, 담당자가 바뀌어도 지원이 끊기지 않는다

전문위원의 업무 개선은 목적이 아니라 임팩트에 이르는 경로다. 최종적으로 측정하려는 것은 청년이 세운 목표의 달성이다.

왜 지금은 그 목표가 달성되지 않는가

청년의 재무 문제는 한 번의 상담으로 끝나지 않는다. 여러 회차에 걸쳐 목표를 쪼개고, 과제를 수행하고, 다시 확인하는 과정이 누적되어야 달성된다. 그런데 이 누적이 실제로는 끊긴다.

  • 상담 기록이 전문위원 개인의 문서에 흩어져 있어, 다음 회차를 준비할 때 과거 맥락을 다시 재구성해야 한다.
  • 지난 회차에서 정한 과제와 물어볼 것이 다음 회차로 넘어가지 않아, 확인 없이 지나간다.
  • 같은 질문이 반복되고, 회차별 목표가 전체 목표에서 조금씩 벗어난다.

즉 문제는 상담의 질이 아니라 회차와 회차 사이가 끊긴다는 것이다. 릴레이어는 이 사이를 잇는 도구다.

경로의 논리

도구가 모든 회차를 기억해 흐름이 이해된다 → 같은 질문과 과제를 반복하지 않고 대화가 늘어지지 않는다 → 회차별 목표를 전체 목표에 정렬해 설계할 수 있다 → 회차별 목표 달성률이 오른다 → 청년의 전체 상담 목표 달성률이 오른다

이 경로에서 앞 단계는 뒤 단계의 조건이다. 따라서 임팩트 측정도 단계별로 나누어, 어디까지 확인되었고 어디가 남았는지를 구분해 관리한다.

이 문제를 다루는 조직으로서의 전제

우리 기관은 중간지원조직이다. 사업 담당자는 기획·운영·연계를 맡고, 실제로 청년을 만나 관계를 맺고 상담을 이끄는 것은 위촉된 전문위원(프리랜서 재무 컨설턴트)이다. 담당자는 상담 현장에 상시로 있지 않다.

그래서 이 사업의 핵심 전제는 다음과 같다. 사회복지 실천의 핵심 원칙은 효율성이 아니라 목표지향적 개입이다. 전문위원의 일하는 방식은 관계적이고 목표지향적이며, 정보를 줄이는 것보다 당사자와의 관계와 목표 흐름을 놓치지 않는 것을 우선한다. 임팩트를 설계하는 모든 판단은 이 전제에서 나온다.

임팩트 경로상 가장 중요한 진전이다. 청년이 상담에서 정한 과제를 실제로 수행하고 확인받는 비율이 올랐다는 것은, 목표가 회차를 넘어 이어지기 시작했다는 뜻이다. 전문위원 FGI에서 확인된 기제는 두 가지다.

  • 당사자의 성향이 파악되어 과제를 더 구체적으로 설계할 수 있었다. 지난 회차 기록이 그대로 올라오면서 이 청년이 무엇에 어떻게 반응하고 무엇을 어려워하는지가 보이고, 그에 맞춰 확인할 과제를 세밀하게 잡을 수 있었다.
  • 상담 중에도 확인할 것이 화면에서 사라지지 않았다. 기록지 좌측에 상시 노출되므로, 대화가 다른 주제로 흘러가도 놓치지 않고 다시 가져올 수 있었다.

3.2시행착오와 개선

초기 가설과 그 전제

상담 전 준비 시간이 길어 부담이 크다. 요약본과 확인할 것을 보여주면 준비 부담이 줄어들 것이다.

이 가설은 사업 담당자 본인의 업무 감각에서 출발했다. 담당자는 청년을 상시로 만나지 않고 위기 상황이나 연계가 필요할 때 간헐적으로 소통한다. 약속 없이 찾아온 청년을 마주할 때 시간 부족으로 상담 기록을 충분히 읽지 못한 채 상담을 시작하는 일이 있었고, 그래서 같은 질문을 반복하거나 이미 지난 이야기로 상담을 시작하게 되는 경우가 있었다. 여기서 "짧은 시간에 핵심만 파악하는 효율적 읽기"가 해답이라고 보았고, 접근 방식은 정보량을 줄이는 요약에 맞춰졌다.

01

전문위원은 프리랜서로, 한 명에게 쓸 수 있는 시간이 상대적으로 여유 있다.

시간 부족이 문제의 원인이 아니었다.

02

요약이 있어도 원문을 직접 읽는 것을 원칙으로 삼는다.

효율의 문제가 아니라 판단 책임, 즉 신뢰의 문제였다.

03

운영자와 실행자는 역할 구조상 서로 다른 문제를 겪는다.

운영자의 업무 감각을 실행자의 것으로 가정한 것이 출발점의 오류였다.

수정된 가설

정보를 줄여주는 것이 아니라, 원문은 그대로 두면서 회차 간 놓친 맥락(과제·목표·불일치)을 이어주면, 전문위원이 목표지향적으로 상담을 이어갈 수 있고, 그 결과 청년의 상담 목표 달성률이 높아질 것이다.

이 전환에 따라 요약 중심 기능을 줄이고, 불일치 확인·주요 내용 표시·회차 간 연결로 개발 방향을 옮겼다. 준비 시간 단축(80분 → 55분)은 목표가 아니라 부산물로 다루며, 임팩트의 기준은 청년의 목표 달성이다.

남아 있는 한계

  1. 최종 임팩트는 아직 측정되지 않았다. 관찰 기간 중 종결 사례가 없어, 전체 목표 달성률과 달성 소요 회차는 2차 측정으로 이월한다. 현재까지 확인된 것은 임팩트 경로의 중간 단계까지다.
  2. 관찰 기간과 표본이 제한적이다. 상담 2~3회차, 전문위원 21명 규모로는 통계적 유의성을 주장할 수 없다. 이번 결과는 경향성으로 해석한다.
  3. 집단 배정이 무작위가 아니다. 자발적 참여를 기준으로 나누었으므로 두 집단의 차이는 인과관계가 아닌 연관성으로 본다. 2차 측정에서 두 집단의 사전 특성(담당 건수, 경력, 기존 기록 방식)을 함께 비교해 보완한다.
  4. 집단별 측정 방식에 차이가 있다. 실험집단은 도구 사용 기록을, 비교집단은 자가 기록을 사용한 항목이 있어 측정 방식이 결과에 영향을 줄 수 있다. 2차 측정에서는 양 집단 동일 문항·동일 척도로 통일한다.
  5. 저빈도 항목의 차이는 확대 해석할 수 없다. 반복 질문과 과제 중복은 회차가 누적되며 드러나는 문제이므로, 2~3회차 시점의 작은 차이는 신호 수준으로만 본다.
  6. 당사자 관점 자료가 2명 규모다. 임팩트의 최종 수혜자 측 근거가 가장 얇은 부분이며, 2차에서 우선 보완한다.
  7. 회차별 목표 달성률의 판정 기준이 목표 성격마다 다르다. 목표 유형별 달성 기준을 사전에 정의하는 작업이 필요하다.
  8. 수단의 완결성. 수정된 가설의 구성 요소 중 회차 간 맥락을 잇는 누적 기록 기능은 아직 구현 전이다. 현재 결과는 기능의 일부만으로 관찰된 변화이며, 가설의 완전한 검증은 해당 기능 구현 이후다.
  9. 사용 편의성 개선이 필요하다. 전문위원 다수가 금융권 은퇴자로, 현재 화면 구성으로는 기능을 충분히 활용하지 못할 수 있다.

판단은 사람이 한다. 도구가 제시하는 요약·표시·제안은 판단의 근거를 보여주는 데까지이며, 판단은 전문위원이 한다. 실무자 의견란은 도구가 채우지 않는다. 실무자가 확인하기 전까지 도구가 생성한 내용은 사실로 기록되지 않는다.

릴레이어가 전제로 삼은 조직 구조(운영자는 기획·연계·매니징을 맡고, 실제 상담은 위촉된 위원이 수행하는 구조)는 우리 기관만의 특징이 아니라 중간지원조직 전반의 공통 구조다. 따라서 "회차 사이가 끊긴다"는 문제도 공통적으로 발생한다.

민간 영역
  • 자립준비청년 지원 기관. 위탁 사례관리자가 다수의 청년을 담당하는 구조가 동일하다.
  • 사회복지협의회·지역자활센터. 위촉·프리랜서 상담 인력 중심으로 운영된다.
  • 청소년상담복지센터, 드림스타트 등. 회차형 상담과 사례관리가 핵심 업무다.
공공 영역
  • 사회서비스원·지자체 위탁 사업. 여러 기관에 흩어진 사례관리 기록을 표준화해 관리할 필요가 이미 존재한다.
  • 복지사업 성과 보고. 회차별 목표와 달성 기록이 축적되면, 별도 정리 작업 없이 사업 성과 보고의 근거 자료로 활용할 수 있다.
확산 전략
  1. 레퍼런스 확보파일럿 기관에서 2차 측정까지 완료해 최종 임팩트 데이터를 확보하고, 기존 관리 체계와의 연결을 마친다.
  2. 사전 검증유사 구조 기관 2~3곳을 인터뷰해, 상담 양식과 용어의 차이가 도구 적용에 어떤 조정을 요구하는지 확인한다.
  3. 추가 파일럿자립준비청년 지원 분야 내 1~2개 기관에서 동일한 측정 설계로 파일럿을 진행해, 임팩트가 기관을 바꿔도 재현되는지 검증한다.
  4. 표준 도구 제안축적된 임팩트 데이터를 근거로 공공기관 사례관리 도구로 제안한다.
